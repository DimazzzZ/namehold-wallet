# App knowledge for QA agents

Where things are in Namehold, how its windows behave under automation, the words it uses for a listing's states, and the issues already known. Exact sentences a case checks are quoted in that case; this file holds what many cases share.

## Where things are

- **Sidebar**, top to bottom: "Namehold" with a `Beta` badge (hover: the beta warning); the wallet switcher card (label, `Hot · Mainnet` / `Ledger · …` / `Watch-only · …`; click → the wallet menu: every wallet with ✓ on the active one, `Add wallet`, `Manage wallets…`) with the lock button beside it (hot wallets only); Wallet, Names (`/auctions` and `/watchlist` redirect there), Market (tagged "New"), Activity, Settings (`Settings` / `Import from Namebase` tabs for now; `/migration` redirects there). Names and Activity show an amber count when something needs you / is left to finish. Hotkeys 1–5 follow the order. On testnet or regtest a coloured strip at the top names the network.
- **Wallet page**: `Sync`; the balance card (Spendable, the muted line Unconfirmed / Immature / Locked in auctions / Name value; after a sync that could not read the wallet's coins from the node, an amber line: "Your node can't report this wallet's coins: <the reason the sync recorded>"), `Send` and `Receive` (a dialog: the address + QR, `Copy address`, `Explorer` on mainnet, `New address`, `All addresses`, the xpub under Advanced); **Needs you** (one row per task with Reveal / Renew / Finalize / Register / Redeem); **Your names** (the 5 most urgent, `All N names` opens Names › Owned); Recent activity (5 rows). The signer, node and sync state live in the readiness pill at the top right (click it for Lock/Unlock, the node's Start / Stop / Re-sync, `Sync now`, last sync).
- **Names page** (`/names`): a lookup field (`Look up`; a known name opens, a new one shows a card with `Open auction…` / `Watch`), chips `All · Needs you · In auction · Owned · Watching` with counts, `Filter…`, one table row per name (owned, bid on, bought, listed or watched; ★ and tags for watched ones; a row click opens the name), a checkbox per owned row and, once a name is selected, the batch bar (`Renew Selected`, `Reveal Selected`, `Redeem Selected`, `Finalize Selected`, `Transfer Selected…` which then asks for the recipient in a dialog with `Review`, fee rate override; with nothing selected only `Select all N transferable` shows), a `More` (⋯) menu on every row (`Open name`, the name's allowed `Renew` / `Reveal` / `Redeem` / `Finalize` run for that name alone, `Cancel transfer…` / `Transfer or sell…` / `Edit DNS records` / `Sign message` open the name page, then `Watch` or `Edit tags` / `Remove from watchlist`), header buttons `Batch bid…`, `Import CSV`, `Export CSV`. A listed name reads `Listed for sale · <listing state>` with a `My listings` button.
- **Names row of a purchase on its way**: no checkbox, the row opens nothing; `Bought · waiting for the purchase to confirm` → `Bought · awaiting finalize · N blocks left` (`1 block`) with `View` → `Bought · ready to finalize` with `Finalize` → `Finalize · waiting for a block` → an ordinary owned row.
- **Name actions** open from a Names row or its button, from Needs you / Your names on Wallet, or from the Names lookup. The Ownership section holds `Transfer`, `Finalize`, `Cancel transfer`, `Sell…`, `Renew`, `Revoke`. A disabled button's reason is a hover hint.
- **Market**: title `Market`, subtitle "Names their owners are selling through Shakedex. Your node checks every listing before you can buy."; `Import listing…` on the right (Browse only); underlined tabs `Browse` and `My listings`. Browse, top to bottom: on mainnet with the Shakedex setting off the banner "Buying on mainnet is off. …" with `Turn on buying`; the `Your purchases` card while a purchase is not finalized (`Paid <price> HNS`, a progress bar with `<done> of <lockup> blocks` or "Ready to finalize", `~<time> left` on mainnet and testnet (`<n> blocks left` on regtest) or `Finalize`, filled only while the page shows no other filled button: not beside the banner or a listing's Buy); the list (toolbar `Find a name`, `All` / `Fixed price` / `Price drops`, sort `Lowest price` / `Next price drop` / `Newest`; columns Name · Price now · Next price · Check; rows `✓ Verified`, or `Couldn't check` with `Retry`; at its foot the "unavailable listings hidden" toggle and `Load more` or "All LearnHNS listings loaded") and the listing panel beside it (below it in a narrow window) with the price, `Checked by your node`, the breakdown, `▸ Fee rate`, the three steps Buy · `Wait ~2 days` (`Wait 10 blocks` on regtest) · Finalize, and one full-width button; the panel is never taller than the window from where it starts, so with a long list its button stays in sight and the rest scrolls inside it. Off mainnet the list reads "Nothing is listed right now" / "There is no LearnHNS Market on this network. If a seller sent you a listing directly, import it." `Import listing…` opens `Import a listing`: a box for the file's text or a link, `Choose a file…`, `Cancel`, and `Import` (or `Import link` for text starting with `http(s)://`; `Checking…` while the node checks it). Imports join the list, tagged `From file` or `From link`. My listings lists the active profile's listings and holds `Find my locks` (a secondary button; beside it the refusal for a profile or node that cannot sell; under it, while the signer is locked and a candidate waits, "Names this recovery phrase may have locked for sale were found. Unlock the wallet to restore them." with `Unlock`, and on a node without the address index "Finding your locks needs a node run with --index-tx and --index-address; Restore a lock by name works without them.") and `Restore a lock by name`.
- **Activity**: a search box ("Search by name..."), an action filter (`All actions`, then one entry per action) and a status filter (`All statuses`, `Confirmed`, `Pending`). Draft rows offer `Sign & broadcast` (unsigned), `Broadcast` (signed), `Retry` (failed or dropped) and `Discard`. A sent, unconfirmed row of ours shows `Speed up` (see Speed up below). A row that moves a name shows its value on a `⤷ <value>` line. On a node without an index the history needs, a yellow banner replaces the list's error: "Your node does not have `--index-address` enabled." (or `--index-tx`, or `--index-address` or `--index-tx`, naming the one the node lacks), then "Restart it with `--index-address --index-tx` to enable full history."
- **Settings**: six sections in a left nav (`?section=connections|node|notifications|import|updates|advanced`; a red dot marks a section with an error, and the save bar's `Show` opens it; `/migration` lands on Backup & import, which holds the bid backup and the Namebase history import). Connections (`Allow sending via remote node`, `Save settings`); Notifications (`Enable deadline notifications`, saved with `Save settings`, which also drives the Shakedex "Ready to finalize" reminders: the background daemon `namehold-syncd` posts those after each of its syncs, every ~60 s, also with the app quit, and the app posts them, on launch and every ~10 minutes, only while the daemon has not run for 3 minutes; with macOS refusing notifications the section reads "OS notifications are blocked for this app. Enable them in your system notification settings — …"); Advanced › Shakedex ("Allow buying and selling names on mainnet through Shakedex (experimental)", with the note "Testnet and regtest are always allowed. Finalizing a purchase, and Finalize & sign, Cancel and Lower price on a listing you already have, work whatever this says.").

## Speed up

- **Where**: a secondary `Speed up` button on every Activity row of ours that is sent and not confirmed (status `Pending` with a draft behind it), except a Speed up child's own row; and under Market › Browse › `Your purchases`, in the right-hand column of a purchase still waiting to be mined ("Waiting for the purchase to be mined"). When the backend refuses, the button stays, disabled, and its hover hint is the reason, for example "Its change is not in your wallet yet; refresh your wallet and try again." (a send not synced yet: press Sync), "This transaction has no change to spend, so it cannot be sped up.", "This transaction is already being sped up.", "This transaction already has a Speed up that was never sent; discard it in Activity (its row offers Discard) to speed this one up again.", "This transaction waits on another unconfirmed transaction of the mempool; speed that one up, or wait for it to confirm.", "This transaction is not waiting in your node's mempool, so a child could not pull it into a block. If it was not mined, send it again instead.", "Speeding up needs a full or remote node: SPV and Explorer modes cannot read the mempool." In the browser preview it is always disabled with "Speeding up needs your node's mempool, which the browser preview does not have."
- **The form** (`Speed up` dialog): a paragraph saying a second transaction spends this one's change and pays for both, that the fee goes to the network only (a purchase adds that the seller's price and the purchase itself are unchanged) and that the original keeps its transaction id; `Fee rate (doos/vB)` (empty: "your node's estimate"); the rows `This transaction` (`<n> vbytes, fee <fee> HNS`), `Fee rate now`, `Target` (`<n> doos/vB (your node's estimate)`, or `(the rate you chose)`), `Speed-up fee`, `Fee rate with it`, `Change left`, `Mempool deadline`; then the amber sentence "Speeding up does not extend the 72 hours your node keeps the original transaction: if it is not mined by <date>, both are dropped and nothing is paid by either."; `Cancel` and `Review and sign`. A refusal replaces the rows with the backend's sentence in red, for example "Your transaction already pays this rate or more; choose a higher one." (on regtest the node has no estimate, so an empty rate reads "Your node has no fee estimate yet, and this transaction already pays the minimum rate; choose a higher one.": type a rate).
- **The secure window** is `Confirm transaction` with the rows Action `Speed up`, Speeds up `<parent txid>`, Fee, Fee rate (`<now> now, <after> with this fee (target <n> doos/vB, <source>)`), Paid to ("The network only: nobody else is paid.", plus the purchase sentence), Back to your wallet (the change left), Original transaction ("It keeps its transaction id."), Deadline (the 72-hour sentence, in UTC), Txid. Declining it discards the child, so the parent's `Speed up` is offered again.
- **After**: the toast `Speed up sent <first 12 hex of the child's txid>…`; the child's row is labelled `Speed up` with "Speeds up <first 10 of the parent's txid>…" under it, and the parent's row "Sped up by <first 10 of the child's txid>…". A child whose parent never confirms ends `Not confirmed` with "The transaction it sped up (<txid>) did not confirm, so this one can never confirm. Nothing was paid by either."

## Amounts

Amounts are written with six decimals everywhere: `5.000000 HNS`, `0.050000 HNS`. A case that writes `5 HNS` in a quoted UI string means `5.000000 HNS`. A backend refusal shown in the UI may carry the prefix "Invalid input: " or "Broadcast failed: "; that prefix is fine.

## Secure windows and native panels

- Signing happens in a **secure window**, a separate window of the same process. When the signer is locked, the first secure window asks for the wallet passphrase (`Wallet passphrase`); after it, the action's own secure window opens (for example `Confirm cancel`, `Confirm Finalize & sign`, `Confirm Lower price`, `Confirm transaction`) and is confirmed with `Confirm & Sign` or declined with `Cancel`. Declining shows "Confirmation declined" in the dialog that asked.
- Find secure windows again after every action that opens one; they may open behind the main window or on another macOS Space.
- The native **Save** and **Open** panels (export, own-file import, `choose a file…`) are separate windows, possibly of another process (the macOS panel service). Type the path into the name field, or use `cmd+shift+g` (Go to folder).
- If the human maintainer watches the run, a secure window may be confirmed by them by hand; note who confirmed each signature.

## Driving the app

Any GUI driver works: computer use, or an accessibility driver such as cua-driver (`list_windows`, `get_window_state`, element actions by snapshot index). Lessons learned with this app (WebKit inside Tauri):

- Re-snapshot before every element action; indices change on every render. An element action needs the snapshot it came from.
- A background press by element index usually works and may report its effect as unverifiable; verify with a fresh snapshot or a screenshot.
- An HTML `<select>` (for example the onboarding network dropdown) has no accessibility children and cannot be set by value; focus it and press `down` (foreground) until the option shows, then `return`.
- If typing into a text field by element index does not show up in the next snapshot, click the field by window-local pixel coordinates and type; as a last resort use foreground delivery.
- Foreground actions briefly raise the app window; keep them to what is needed.
- Hover hints (a disabled button's reason) are often not exposed to accessibility. A case that needs the hover text and cannot read it is ◐, not ❌.
- Toasts are transient and easy to miss between two snapshots. A missed toast is ◐ with the reason, never ❌; when it matters, snapshot right after the confirm.

## Listing states

The same label on Owned Names and on the My listings badge (`src/components/market/marketText.ts`). Which buttons a state shows in My listings is fixed; whether each is enabled is the backend's, and every disabled button's reason is printed once under the row.

| State | Label | My listings buttons |
|---|---|---|
| locking | `Locking`, or `Locking · N blocks` once the lock is mined | Finalize & sign |
| readyToFinalize | `Ready to Finalize & sign` | Finalize & sign |
| finalizing | `Finalizing into the lock` | none |
| listed | `Listed for sale` | Lower price, Cancel listing, Export listing file (Publish on LearnHNS Market: mainnet only) |
| salePending | `Sale pending` | Export listing file |
| sold | `Sold` | none |
| cancelling | `Cancelling` | Lower price, Export listing file |
| cancelAwaitingFinalize | `Cancelled · finalize to bring it home` | Finalize home, Export listing file |
| cancelFinalizing | `Coming home` | Export listing file |
| cancelled | `Cancelled` | none |
| aborted | `Lock aborted` | none |
| restored | `Locked — listing details unknown` | Cancel listing, Import its listing file |
| expired | `Expired in the lock` | none |

- A row with its own unsent transaction also shows `Sign and send` (unsigned) or `Send` (signed), and `Discard`; a transaction the node may already hold shows `Send` and no `Discard`.
- The mode next to the name is `Buy now` or `Reverse auction`; a Restored lock shows none.
- The price line shows **only on Listed rows**: Buy Now `Price 5.000000 HNS`; reverse auction `Now X HNS · next Y HNS in ~T · floor Z HNS` (or `No price step valid yet · …`); node unreachable `Current price could not be checked: <reason>`. A Listed row with more than one signed step (a reverse auction, or a Buy Now after a Lower price) also has the disclosure `All N price steps`, one line `<price> HNS — from <date time>` per step; that is correct for a lowered Buy Now too. Under it: `Listed until <date> · this date does not end the listing`. Wait texts read `~N min`, `~N h`, `~N d`.
- A Listed or Restored row whose name gets within 30 days (4320 blocks on mainnet; half the renewal window where that is shorter: 2160 on testnet; 300 on regtest) of being too close to expiring to finalize a purchase shows one amber line: `Buyers stop seeing this listing in ~N days, when the name gets too close to expiring to finalize a purchase. Cancel it and bring the name home to renew it, then list it again.` (`in N blocks` on regtest and simnet; `in less than a day` under a day), and past that point `Buyers no longer see this listing: the name is too close to expiring to finalize a purchase. Cancel it and bring the name home to renew it.` Without a full or remote node there is no such line. In the browser mock a restored lock of `urgent` shows it (`~6 days`).
- Off mainnet every row's market status line reads `Shared as a file only: LearnHNS Market lists mainnet names only`.
- A Listed row another device or profile of the same phrase manages (LearnHNS Market showed a price step this device never signed) reads, in place of its market status and with the amber dot, `Managed from another device: LearnHNS Market shows a price this device never signed, so this device no longer uploads the listing. It still follows the chain.`, then `Price set on the other device: N HNS. Anyone can buy at it until the listing is cancelled.`; its price line ends `— on this device`. It shows two more buttons, `Manage from this device` (a dialog naming the other device's price, then `Manage from this device` or `Leave it`; nothing is signed, so no secure window) and `Import its listing file`, and under the buttons "The listing file holds only this device's prices, not the one set on the other device." `Lower price` is disabled with "another device or profile with your recovery phrase manages this listing: lower its price there, or manage it from this device first". The Cancel dialog adds "The price set on the other device (N HNS) can be bought too until this cancel is mined." The browser mock has one device, so no row there is ever managed elsewhere; drive it in the native app with two profiles of one phrase on mainnet. A Sold row may read `Sold at a price set on another device`, a cancelled one `Cancelled from another device or profile with your recovery phrase`.

## Activity labels for Shakedex

A Shakedex draft is labelled by what it does, and keeps that label after its transaction is seen on chain: `Buy`, `Finalize purchase`, `Lock for sale`, `Finalize into lock`, `Cancel listing`, `Finalize cancel`. A row this device has no draft for (made on another device or profile of the same phrase) shows the chain's generic label (`Transfer`, `Finalize`); that is not a finding.

Amounts on those rows: a purchase shows minus the price (not the name's value); a seller's cancel and a buyer's FINALIZE show 0 with a `⤷ <name value>` line; the fee is shown separately. A lost purchase carries the badge `Lost` with its reason under it.

## Known quirks and their workarounds

- **The window may open on another macOS Space**; switch to it before capturing.
- **Transient toasts and hover hints** are easy to miss: record ◐ with what was seen, not ❌.
- **Quitting with a secure window open**: `cmd+Q` may not close the app while a secure window is up; use the app menu's Quit, or `osascript -e 'tell application "Namehold" to quit'`, and as a last resort `pkill -x namehold-wallet`.

## Known issues NOT to report again

These are recorded and known. Note what you see if a case runs into one, but file it again only if its behaviour changed.

- A name in the Cancelling state shows "Shakedex_cancel is broadcast and waiting to be mined. Nothing changes on-chain until it lands in a block." in its name actions instead of disabled owner buttons.
- Spec §5 "Known gaps" ([the spec](../specs/2026-10-05-shakedex-name-sales.md)) lists behaviour that is by design (one device per listing, a restore sees addresses only up to the gap limit past the last used one, and so on): a case that hits one is ◐ with the gap named, not a bug.
